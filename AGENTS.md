## Protocol (`crates/shared/src/protocol.rs`, `codec.rs`)
- `PROTOCOL_VERSION: u16 = 2`. `ClientCommand.protocol_version` is first field; server rejects mismatch. Bump version on any wire change.
- Framing: 4-byte LE length + postcard payload, 1 MiB max (`MAX_FRAME_SIZE`), non-empty. Use `encode_frame/decode_frame/read_frame/write_frame`; do not invent framing.
- `WorldSnapshot.player` is the per-connection local view; `entities` holds remotes + mobs. `EntityKind` (`Player/Monster/Npc/Item`) drives client visuals, not gameplay.
- Combat is deterministic: `resolve_attack(attacker, defender, tick ^ target_id)`, Manhattan `MELEE_RANGE = 6` (`combat.rs`).
- Collision: deterministic AABB ground-footprint boundaries + diagonal sliding in `crates/shared/src/collision.rs` (`resolve_movement`, `overworld_obstacles`). Both `server::move_player` and `client::apply_local_command` use it; canopy/foliage never blocks. Highway corridor `|x| <= 4` is kept clear.

## Server (`server/src/main.rs`, `lib.rs`)
- `cargo run -p ascii-mmorpg-server` prints loopback demo; `cargo run -p ascii-mmorpg-server -- --tcp 127.0.0.1:4000` serves TCP (multi-client reader/writer threads + one sim thread, per-client `snapshot_for(id)` broadcast).
- `TICK_HZ = 20` is a strict scheduler: the TCP sim thread drains a bounded input queue (`MAX_PENDING = 512`) at tick boundaries — one tick per 50 ms idle or loaded, so burst input coalesces and can never exceed 20 Hz. Protocol mismatches are rejected immediately without ticking. See ADR 0002. `Simulation::advance_tick_with` is the batched entry point; `fixed_tick_for` remains for loopback/tests.

## Client (`client/src/main.rs`, `lib.rs`, `renderer.rs`, `gpu/`, `ui.rs`, `term.rs`)
- Modes: default realtime (`WASD`/arrows move relative to what the orbit camera faces — screen-up walks the camera's forward direction, snapped to the 8 compass dirs; CPU renderer stays world-fixed because it has no camera; hold right mouse + drag to orbit the elevated OSRS-style GPU camera (the player's head and body rotate with it so they keep facing the viewer; `MeshBuffer::add_humanoid` takes a real `facing_angle` and rotates its authored +Z-facing geometry about the foot anchor), `F` attack, `R` rest, `I` inventory, `C` character, `M` map, `P` pause, `V`/`T` cycle weather, `Q`/`Esc` quit); `--line` legacy stdin mode; `--demo` offline demo (6 frames); `--connect ADDR` TCP mode. Camera orbit is client-side presentation only and is unavailable in the CPU renderer/notcurses mouse path. Pause (`ActiveModal::Paused`) freezes local input and shows a large-font menu; `Q` quits directly from pause. Client-side only — the server keeps ticking online.
- `--fps`/`--weather` use `rposition` so CLI overrides `.bat` defaults: `--fps <N|uncapped|max>` (default 60, `0` = uncapped), `--weather <rain|snow|storm>` (default rain). `--notcurses` requires `--features notcurses`.
- GPU is the default feature (`gpu`, alias `wgpu-scene`): offscreen 3D scene → color/normal-depth/entity-metadata targets → WGSL compute ASCII pass (`client/src/gpu/`). Always renders the native terminal grid (never downscaled); SSAA is fixed 4x at every grid size — the compute pass's tap grid/shape regions/thresholds are 4x-locked, and the retired 2x adaptive tier read taps out of bounds (top-left half-grid coverage artifact). The formatter quantizes channels with a two-tier quantizer (2-unit steps under 32 so dark glow halos survive ANSI encode, 32-level run-merging steps above). Shape picking follows Alex Harri's ascii-rendering writeup: six-region internal sampling vector from the SSAA taps, then directional contrast (each component normalized against the max of its *widened* set of outward neighbor texels + corners, `dir_power` 2.0) before the global normalize-then-pow pass (`contrast_power` 1.22); the widened externals are what remove residual boundary staircasing. Glyph variants and Bayer dither hash world-locked tile keys (each cell depth-unprojects to world space via the post-pass `inv_view_proj`, entity 0 only) so a camera pan no longer re-randomizes the ground (the recorded "shower-door" shimmer); actors keep the screen hash. Terrain/grass/fallback ramps stay quiet at bright bands (strokes, then rounded cobblestone loop glyphs on material 0 — the reference never renders stone as `░▒▓█` progress bars; the only remaining block ramp is the unknown-material fallback); structural vertical edges emit `|`; letter detail lives on entity materials so actors pop. Lighting is reference-scaled: compact pools (player lantern radius 5.0, gate torches 4.6, NPC 4.4, monster 3.8, loot 3.0) over a dim ambient/sun wash [0.06,0.08,0.12]/[0.42,0.52,0.72] (the color target is sRGB-encoded, so carpet light energy must sit low; the sea keeps a 1.6x local gain to hold the wave language), emissive material-4 halos spill into `bg` via the stage-clearance scan (`glow_accum`, capped 0.35), and the entity edge rim is monochrome silver 0.35 mix with 8% class accents (hostility lives in nameplates and the target ring). Actor headlight/rim adds trimmed to 0.24/0.28 so bodies don't clip to white once the carpet goes reference-dark; weather ink dimmed ([0.34,0.44,0.62] rain, [0.55,0.60,0.70] snow) to stay a quiet accent over the void. Quiet-ground contract (video-tools REPORT #1, test-enforced): meadow albedo stays dim (material-3 vertices `g <= 0.15`; a world-space clump mask carves ~57% of off-road quads into a near-black void floor [0.002,0.011,0.004] with moss islands pinned [0.012,0.072,0.028] — the reference's clump+void negative space; hue identity: same-luma raised chroma for the reference's saturated carpet) so the ground resolves into the low punctuation bands (`.` `,` `'` `` ` `` `;` `:` `-` `~`, scene median luma 30.8 on the composed 156x44 frame (baseline was 41.8; black% 5.5→23.5), approaching the reference's 20–33), pines/trunks/road sit one notch brighter, sand/water keep their own palettes, and the blade field is a sparse mesh-side tuft population (`seed % 5`, `gy < 32`) and the compute pass density-gates meadow bands 0–3 to 1-in-4 world-locked tuft emissions (material 3), so the carpet stays near-black until a light pool passes — never a per-cell punctuation sheet. The southern ocean starts exactly south of `WORLD_BOUNDS.max_y` (mesh z 28.0 = shared collision bound times the 0.8 world-to-scene scale): a dry-then-wet sand beach, then open water as material 6 driven by one directional rolling swell — the long-swell phase (`t*2.2 + z*0.55`) rolls crest bands north onto the beach, vertex bob and fragment shading share the phases, foam breaks white at the crest (`smoothstep 0.58–0.92`, opaque) with a shallow-to-deep color gradient southward, all feeding the wave glyph ramp; collision untouched (beach rows stay walkable, water sits beyond the world edge). The sea language is quiet by design: calm bands stay empty, band 2 is a pure `~`, band 3 mixes `~`/`=`, foam caps break `=`/`~`/`*` — no letters and no stroke overrides on water (material 6 gets `water_surface` in `shape_glyph`), spec 0.6/fresnel 0.10 keep distant water out of mid bands; procedural trees stop at `tree_wy < 32` and grass at `gy < 32` so nothing greens the beach or the sea. Character-model shading (Harri cel-shading separation + kciter headlight/rim, test-pinned in shaders.rs) applies only to entity fragments (`in.entity_id > 0.5`): the sun's NdotL is quantized into 4 stepped bands, camera-facing surfaces get the headlight term, silhouettes get a faint rim — terrain/props keep the smooth dark-carpet lighting. Character-clarity pack (clarity study, `video-tools/REPORT.md`): (A) every actor floats a dark-backed nameplate with white name + red HP mini-bar/digits drawn into the composed buffer via `ui::draw_scene_labels` from `gpu/renderer.rs` `compute_scene_labels`, which projects feet/head with the same `view_proj` the mesh pass used (player label tracks the smoothed render position; CPU path passes `&[]`); (C) the nearest living monster in melee range (the same rule `Command::Attack` resolves) gets an orange dashed ground ring via the label's `is_target`; (B) stage clearance (test-pinned): ground cells (entity_id 0) within a ±3-cell scan of any actor emit pure space so silhouettes stand on a locally uniform floor, the outer shell dithers by `hash2(x, y)` for a ragged arena edge, and rain/props/terrain/actor surfaces are untouched. Combat FX pack (video-tools REPORT #2+#3, GPU path only): the renderer watches the snapshot combat log presentation-side — `MeshBuffer::add_impact_burst` (solid white-hot core → expanding ground ring → rising embers, 0.45 s) fires at the named target on `You hit {name} for …` messages, and `MeshBuffer::add_ground_ring` dashes sweep inward during `You cast {spell}` wind-ups (per-school hue: Cleave amber, Iron Will cyan, Thunder Mark blue) before resolving into the burst; FX quads are emissive material 4 stamped with reserved entity id 254 / class 0 (accepts the authored hue — the monochrome rim mix is class-agnostic silver, so quads this small keep their color), deduped by message, capped 16, expiring by telegraph+burst time; timelines key off `animation_time` so deterministic builds stay deterministic (observation is skipped in the deterministic path), and the CPU fallback shows no FX and no labels. Metadata invariant (test-enforced): `set_entity_context` maps the reserved "no entity" id 0 to metadata 0 — the 1-based wrap `((id-1) % 255) + 1` previously folded 0 → 1 so every terrain/prop vertex carried entity_id 1 and any `entity_id > 0` shader gate lit the whole landscape. Falls back to CPU renderer automatically on init failure; `--cpu` forces fallback. `--wgpu-demo [N] [WxH]` is the headless benchmark (optional size simulates zoomed-out grids). There is no `--wgpu` realtime flag.

## Performance (windowed presenter, `--features present`)
- **Run with `--release`.** Debug builds are typically 5-10x slower for the CPU rasterizer + wgpu validation layers. The `play` example at 10 FPS in debug is expected; `--release` is the single biggest win.
  - `cargo run --locked -p ascii-mmorpg-engine --features present --release --example play`
- The 3D triangle fill moved to the **GPU** (`engine/src/present/gpu3d.rs`, wgpu compute): the CPU pre-pass (clip→project→shade, `raster::`'s own math) uploads screened triangles + 64-sample tile bins, and one compute thread per 2x sample replays `raster::fill_tri`'s exact edge/barycentric/depth math — output is **bit-identical** to the CPU fill (test `gpu_resolve_matches_cpu_fill`, 100% cell match), so `resolve_layer` (glyphs, fog, rim) stays on the CPU unchanged. `--cpu` on `play` keeps the full CPU fill. Remaining CPU costs per frame: `resolve_layer` (~3-5ms) and the buffer readback (~2-3ms) — moving resolve into WGSL is the next lever, not a quick toggle.
- Frame timing breakdown: `PRESENT_PROFILE=1 cargo run ... --example play` prints per-frame `build` (scene construction), `compose` (CPU composition), and `inst` (instance flattening) timings every 60 frames, plus a `[world3d]` per-stage line (pre/bins/sub/poll/map+dec/resolve) each frame while the env var is set.
- Current 2026-10-18 implementation note: the windowed compute fill uses the fixed 4x4 `raster::SAMPLE_GRID` and 68-byte `GpuTri` records with normal/material metadata; the older `2x sample` wording in the historical paragraph above is superseded.
- `apply_rim` in `engine/src/raster.rs` was O(n²) (linear cell search per silhouette cell) and is now O(n) via direct mutable iteration over the already-built coverage grid.
