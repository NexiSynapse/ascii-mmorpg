## Protocol (`crates/shared/src/protocol.rs`, `codec.rs`)
- `PROTOCOL_VERSION: u16 = 2`. `ClientCommand.protocol_version` is first field; server rejects mismatch. Bump version on any wire change.
- Framing: 4-byte LE length + postcard payload, 1 MiB max (`MAX_FRAME_SIZE`), non-empty. Use `encode_frame/decode_frame/read_frame/write_frame`; do not invent framing.
- `WorldSnapshot.player` is the per-connection local view; `entities` holds remotes + mobs. `EntityKind` (`Player/Monster/Npc/Item`) drives client visuals, not gameplay.
- Combat is deterministic: `resolve_attack(attacker, defender, tick ^ target_id)`, Manhattan `MELEE_RANGE = 6` (`combat.rs`).
- Collision: deterministic AABB ground-footprint boundaries + diagonal sliding in `crates/shared/src/collision.rs` (`resolve_movement`, `overworld_obstacles`). Both `server::move_player` and `client::apply_local_command` use it; canopy/foliage never blocks. Highway corridor `|x| <= 4` is kept clear.

## Server (`server/src/main.rs`, `lib.rs`)
- `cargo run -p ascii-mmorpg-server` prints loopback demo; `cargo run -p ascii-mmorpg-server -- --tcp 127.0.0.1:4000` serves TCP (multi-client reader/writer threads + one sim thread, per-client `snapshot_for(id)` broadcast).
- `TICK_HZ = 20` is a strict scheduler: the TCP sim thread drains a bounded input queue (`MAX_PENDING = 512`) at tick boundaries — one tick per 50 ms idle or loaded, so burst input coalesces and can never exceed 20 Hz. Protocol mismatches are rejected immediately without ticking. See ADR 0002. `Simulation::advance_tick_with` is the batched entry point; `fixed_tick_for` remains for loopback/tests.

## Client (`client/src/main.rs`, `lib.rs`, `renderer.rs`, `gpu/`, `ui.rs`, `term.rs`)
- Modes: default realtime (`WASD`/arrows move relative to what the orbit camera faces — screen-up walks the camera's forward direction, snapped to the 8 compass dirs; CPU renderer stays world-fixed because it has no camera; hold right mouse + drag to orbit the elevated OSRS-style GPU camera (the player's head and body rotate with it so they keep facing the viewer; `MeshBuffer::add_humanoid` takes a real `facing_angle` and rotates its authored +Z-facing geometry about the foot anchor), `F` attack, `R` rest, `I` inventory, `C` character, `M` map, `P` pause, `V`/`T` cycle weather, `Q`/`Esc` quit); `--line` legacy stdin mode; `--demo` offline demo (6 frames); `--connect ADDR` TCP mode. Camera orbit is client-side presentation only and is unavailable in the CPU renderer/notcurses mouse path. Pause (`ActiveModal::Paused`) freezes local input and shows a large-font menu; `Q` quits directly from pause. Client-side only — the server keeps ticking online.
- `--fps`/`--weather` use `rposition` so CLI overrides `.bat` defaults: `--fps <N|uncapped|max>` (default 60, `0` = uncapped), `--weather <rain|snow|storm>` (default rain). `--notcurses` requires `--features notcurses`.
- GPU is the default feature (`gpu`, alias `wgpu-scene`): offscreen 3D scene → color/normal-depth/entity-metadata targets → WGSL compute ASCII pass (`client/src/gpu/`). Always renders the native terminal grid (never downscaled); SSAA is fixed 4x at every grid size — the compute pass's tap grid/shape regions/thresholds are 4x-locked, and the retired 2x adaptive tier read taps out of bounds (top-left half-grid coverage artifact). The formatter quantizes channels to 32 levels for ANSI run-merging. Shape picking follows Alex Harri's ascii-rendering writeup: six-region internal sampling vector from the SSAA taps, then directional contrast (each component normalized against the max of its *widened* set of outward neighbor texels + corners, `dir_power` 2.0) before the global normalize-then-pow pass (`contrast_power` 1.22); the widened externals are what remove residual boundary staircasing. Terrain/grass/fallback ramps stay quiet at bright bands (strokes, then `░▒▓█` light pools — never alphabet texture); structural vertical edges emit `|`; letter detail lives on entity materials so actors pop. Quiet-ground contract (video-tools REPORT #1, test-enforced): meadow albedo stays dim (material-3 vertices `g <= 0.15`, pinned [0.012,0.072,0.028]; hue identity: same-luma raised chroma for the reference's saturated carpet) so the ground resolves into the low punctuation bands (`.` `,` `'` `` ` `` `;` `:` `-` `~`, scene median fg luma ~33/255 = the reference's 20–33), pines/trunks/road sit one notch brighter, sand/water keep their own palettes, and the blade field is a sparse 1-in-5 tuft population (`seed % 5`, `gy < 32`), not a per-cell carpet. The southern ocean starts exactly south of `WORLD_BOUNDS.max_y` (mesh z 28.0 = shared collision bound times the 0.8 world-to-scene scale): a dry-then-wet sand beach, then open water as material 6 driven by one directional rolling swell — the long-swell phase (`t*2.2 + z*0.55`) rolls crest bands north onto the beach, vertex bob and fragment shading share the phases, foam breaks white at the crest (`smoothstep 0.58–0.92`, opaque) with a shallow-to-deep color gradient southward, all feeding the wave glyph ramp; collision untouched (beach rows stay walkable, water sits beyond the world edge). The sea language is quiet by design: calm bands stay empty, band 2 is a pure `~`, band 3 mixes `~`/`=`, foam caps break `=`/`~`/`*` — no letters and no stroke overrides on water (material 6 gets `water_surface` in `shape_glyph`), spec 0.6/fresnel 0.10 keep distant water out of mid bands; procedural trees stop at `tree_wy < 32` and grass at `gy < 32` so nothing greens the beach or the sea. Character-model shading (Harri cel-shading separation + kciter headlight/rim, test-pinned in shaders.rs) applies only to entity fragments (`in.entity_id > 0.5`): the sun's NdotL is quantized into 4 stepped bands, camera-facing surfaces get the headlight term, silhouettes get a faint rim — terrain/props keep the smooth dark-carpet lighting. Character-clarity pack (clarity study, `video-tools/REPORT.md`): (A) every actor floats a dark-backed nameplate with white name + red HP mini-bar/digits drawn into the composed buffer via `ui::draw_scene_labels` from `gpu/renderer.rs` `compute_scene_labels`, which projects feet/head with the same `view_proj` the mesh pass used (player label tracks the smoothed render position; CPU path passes `&[]`); (C) the nearest living monster in melee range (the same rule `Command::Attack` resolves) gets an orange dashed ground ring via the label's `is_target`; (B) stage clearance (test-pinned): ground cells (entity_id 0) within a ±3-cell scan of any actor emit pure space so silhouettes stand on a locally uniform floor, the outer shell dithers by `hash2(x, y)` for a ragged arena edge, and rain/props/terrain/actor surfaces are untouched. Combat FX pack (video-tools REPORT #2+#3, GPU path only): the renderer watches the snapshot combat log presentation-side — `MeshBuffer::add_impact_burst` (solid white-hot core → expanding ground ring → rising embers, 0.45 s) fires at the named target on `You hit {name} for …` messages, and `MeshBuffer::add_ground_ring` dashes sweep inward during `You cast {spell}` wind-ups (per-school hue: Cleave amber, Iron Will cyan, Thunder Mark blue) before resolving into the burst; FX quads are emissive material 4 stamped with reserved entity id 254 / class 0 (class 0 keeps the authored hue — the post pass tints every edge cell 60% toward the class color, which swamps quads this small), deduped by message, capped 16, expiring by telegraph+burst time; timelines key off `animation_time` so deterministic builds stay deterministic (observation is skipped in the deterministic path), and the CPU fallback shows no FX and no labels. Metadata invariant (test-enforced): `set_entity_context` maps the reserved "no entity" id 0 to metadata 0 — the 1-based wrap `((id-1) % 255) + 1` previously folded 0 → 1 so every terrain/prop vertex carried entity_id 1 and any `entity_id > 0` shader gate lit the whole landscape. Falls back to CPU renderer automatically on init failure; `--cpu` forces fallback. `--wgpu-demo [N] [WxH]` is the headless benchmark (optional size simulates zoomed-out grids). There is no `--wgpu` realtime flag.
- `PlainTerminal` is a differential dirty-line rasterizer (`\x1b[{row};1H` + `\x1b[K`, full repaint only on line-count change or resize) to avoid Windows ConPTY tearing. Preserve that behavior. `client/src/term.rs` (`CellMatrix`, span-diff encoder) and Ratatui HUD in `client/src/ui.rs` feed through the same ANSI path.
- Terminal backends stay behind `Terminal` trait in `client/src/lib.rs`. Input must come from each backend's own reader via `Terminal::next_key` (notcurses owns the tty, so crossterm must never touch stdin in `--notcurses` mode — keys silently die; releases need kitty protocol, hence `decay_held_keys`). Keep bindings out of gameplay/renderer code. Frames compose in one Ratatui buffer (`RatatuiHud::render_composed_frame` + `ComposedScene` spec in `client/src/ui.rs`): HUD top bar, blitted scene (`partitions::SceneCell`/`blit_scene`), side minimap/threat panel (terminals ≥64 cols), log strip, legend, modal overlay with `Clear` occlusion. Output is always exactly terminal-sized. CPU inks lower via `Ink::rgb`; GPU cells map directly (quantized). Minimap stays inside the HUD (no extra GPU pass).
- GPU monster dispatch keys off label text (`warrior` → champion, `skeleton` → skeleton, else mossling) in `gpu/renderer.rs`; CPU asset selection mirrors it in `assets.rs`.

## Assets (`assets/ascii/`, `assets/ASSET_SOURCES.md`)
- Frames are `include_str!`-embedded, `---` on its own line separates animation frames; runtime never reads asset files from disk. Item icons key off label text (`sword`/`shield`/generic). Separator matching is line-based, so art may safely contain runs like `|---|`.
- `assets/ascii/MANIFEST.md` lists the real visual inputs; `assets/source/kenney/` (CC0) are reference-only, never loaded. Do not bulk-copy outside art without recording exact license/attribution in `ASSET_SOURCES.md`.

## Content (`content/*.ron`, `tools/`)
- `cargo run -p ascii-mmorpg-tools -- content` validates `content/` (default arg is `content` dir). Enforces: exactly 3 spells, non-empty items, ≥2 zones, monster `loot` refs exist, loot weights > 0, `min <= max` with `min > 0`.
- Bot smoke: start server with `--tcp`, then `cargo run -p ascii-mmorpg-bot -- 127.0.0.1:4000 10`.
- `video-tools/` (python, standalone): ffmpeg+OpenCV video-understanding pipeline for the reference captures in `../../data/videos/` (game never loads them). `analyze`/`zoom` CLI, thresholds + known limitations in `video-tools/README.md`, timestamped findings + look-parity port list in `video-tools/REPORT.md`, outputs in `video-tools/out/`.

## Launchers (`play_*.bat`)
- Path-independent via `%~dp0`; never hardcode install paths. Exe lookup prefers `target\release`, falls back to `target\debug`; all default `--fps uncapped`.
- `play_notcurses.bat` probes `target\x86_64-pc-windows-gnu\{release,debug}` first, resolves MSYS2 UCRT64 via `%MSYS2_ROOT%` (default `C:\msys64`, fallback `C:\tools\msys64`), warns instead of failing if absent, keeps `chcp 65001`. `play_wezterm*.bat` must keep targeting `wezterm-gui.exe start --always-new-process` (wrapper `wezterm.exe` detaches early → error 10054).
